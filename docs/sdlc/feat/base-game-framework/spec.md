# Spec: 开始界面与生存计分流程（来自 intent.md）
作者：lyd。状态：已批准。

一句话：新增开始场景与游戏 HUD/结算流程，10 点血量、碰触扣血、击杀计分、存活计时，BGM 全程循环。

## 需求
R1 开始场景：游戏启动进入开始场景，白底、画面中央只有一个「开始游戏」按钮；点击后启动世界场景。
R2 资源：将 chomp.mp3、2.75.mp3 复制到 `resource/audio/`，经 Vite URL 导入并加载；不新增依赖。
R3 BGM：2.75.mp3 循环播放，从开始界面点按钮时启动；跨进入游戏、结算、再来一局保持同一实例连续播放，不重头、不叠音。
R4 游戏状态：每局初始血量 10、分数 0、存活计时 0；点击「开始游戏」或「再来一局」时开始计时。
R5 HUD：世界场景顶部固定（不随相机移动）显示计时（mm:ss）、分数、血量「当前/10」；仅游戏进行中刷新。
R6 受伤：僵尸与主角重叠时扣 1 点血并播放 chomp 音效，僵尸按现有逻辑销毁；每只僵尸最多触发一次，不加无敌帧、击退或额外扣血。
R7 计分：僵尸因飞镖伤害死亡时分数 +1；碰触主角而销毁的僵尸不计分。
R8 结算：血量降至 0 时停止计时、停止僵尸生成与更新、停止战斗判定并冻结 HUD 更新，弹出结算层。
R9 结算内容：半透明遮罩居中面板，显示「分数」「存活时间」与「再来一局」按钮；不显示开始界面内容。
R10 再来一局：点击直接重启世界场景，重置血量、分数、计时与场上僵尸、飞镖，立即开始新一局；不回到开始场景，BGM 继续。
R11 场景注册：main 中按「开始场景 → 世界场景」顺序注册；世界场景不再作为默认入口。

## 风险与分歧
C1 计时格式定为 mm:ss，分钟不补零、秒补零（例 0:07、2:35）。
C2 结算界面按遮罩 + 居中面板实现，样式从简，不引入 DOM 层。
C3 再来一局采用世界场景重启，而非切回开始场景（已定）。
C4 击杀以现有僵尸死亡回调为准；接触销毁不进入死亡动画，也不计分。
C5 BGM 由首次点击「开始游戏」解锁播放，符合浏览器自动播放限制；音量保持默认，不做设置项。
C6 血量仅数字展示，不做心形图标与受击闪烁。

## 设计
- 新增 `StartScene`：负责 BGM 启动入口与居中按钮，点击后 `scene.start('world')`。
- `WorldScene` 内维护本局状态（血量、分数、开始时间、gameOver 标记）与顶部 HUD；HUD 元素设 `scrollFactor(0)` 并置顶。
- 受伤接入现有 `ZombieManager.onReachPlayer` 回调，音效经场景 sound 播放。
- 计分接入现有僵尸死亡回调；存活时间按场景时钟累计并在 update 中格式化。
- 血量归零后置 gameOver 标记，update 内跳过玩家、武器、僵尸、战斗更新并展示结算层；按钮回调 `scene.restart()`。
- BGM 使用游戏级 sound manager，在开始场景首次点击时 loop 播放，后续场景不停止、不重新创建。

## 不在范围
- 开始界面标题、说明、设置与音量控制。
- 受击无敌帧、击退、血迹、屏幕震动等打击反馈。
- 最高分记录、持久化存档、暂停功能与移动端适配。
- 更换背景音乐、死亡/胜利专属音乐。
